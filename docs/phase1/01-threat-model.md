
# 1. نموذج التهديد (Threat Model)

المرجعية: STRIDE + ملفات مهاجم (Attacker Personas). مبدأ التصميم الأساسي: **السيرفر صادق في التشغيل لكنه فضولي** (Honest-but-Curious) — أي نفترض أن من يملك Django أو PostgreSQL أو Redis أو التخزين قد يقرأ أي بيانات مخزنة فيها، ونصمم بحيث لا تكشف هذه البيانات المحتوى.

## 1.1 الأصول المحمية

| الأصل | الحساسية | ملاحظات |
|-------|----------|---------|
| نصوص المراسلات والمحادثات | قصوى | يجب ألا تُقرأ إلا على أجهزة المشاركين |
| المرفقات (محتوى وأسماء ملفات) | قصوى | تُشفّر قبل الرفع |
| مفاتيح الهوية والأجهزة الخاصة | قصوى | لا تغادر الجهاز إلا داخل حزمة استعادة مشفرة |
| مفاتيح مجموعات المحادثة | قصوى | تنتقل فقط داخل بروتوكول MLS المُوثّق |
| Recovery Keys | قصوى | لا تصل للسيرفر إطلاقًا |
| بيانات وصفية (مرسل/مستلم/وقت/حجم) | متوسطة | تُقلّص لأدنى حد تشغيلي، وتُقيّد صلاحية الوصول إليها |
| سجل التدقيق | عالية | يثبت عدم وجود تجاوزات، ولا يحتوي أسرارًا |
| التعاميم والموافقات | عالية | محتواها مشفر؛ قرارات الاعتماد موقعة تشفيريًا |
| النسخ الاحتياطية | قصوى | تُفترض تسريبها؛ كل ما فيها مشفر أو بيانات وصفية |

## 1.2 حدود الثقة (Trust Boundaries)

```
[جهاز الموظف: موثوق بعد التحقق] ←TLS+WS→ [Django/Redis/PostgreSQL/Storage: غير موثوق للمحتوى]
        ↑                                    ↑
 جهاز جديد غير معتمد                مدير، Super Admin، DBA، مهاجم داخلي
 (نطاق التحقق من الهوية)             (يملكون بنية التحتية كاملة تقريبًا)
```

- **موثوق:** كود العميل الموقّع بعد تحديثه عبر قناة موثقة (انظر A9)، وعمليات التشفير داخل Web Crypto/WASM.
- **غير موثوق للمحتوى:** Django، PostgreSQL، Redis، التخزين، طابور الإشعارات، النسخ الاحتياطية، سجلات الخوادم.
- **منطقة وسطى:** بيانات الوصفية — السيرفر يحتاجها للتوجيه، لكن وصول الإدارة إليها يُقيّد بنطاق تنظيمي.

## 1.3 ملفات المهاجم

| المعرف | المهاجم | القدرات المفترضة | الهدف |
|--------|---------|------------------|-------|
| A1 | مهاجم شبكة خارجي | MITM، مراقبة حركة، محاولة إعادة تشغيل (Replay)، حجب | قراءة/تعديل الرسائل |
| A2 | مسؤول قاعدة البيانات / نسخ احتياطية مسربة | قراءة كاملة لـ PostgreSQL والتخزين والنسخ الاحتياطية | استخراج نصوص مراسلات أو مفاتيح من المخزن |
| A3 | سيرفر خبيث (اختراق Django أو إدخال كود) | تعديل استجابات API، استبدال مفاتيح عامة، تسجيل الطلبات، حقن محتوى | التخفي خلف صلاحيات أو كسر الثقة بالمفاتيح العامة |
| A4 | إداري مركزي (Super Admin / مدير تنفيذي) | كل الصلاحيات التطبيقية الشرعية | قراءة مراسلات مرؤوسيه «للضرورة الإدارية» — **يجب أن يستحيل تقنيًا** |
| A5 | مدير مباشر | صلاحيات إدارية على وحدة تنظيمية | قراءة مراسلات موظفه الشخصية أو الجماعية — **يستحيل تقنيًا** |
| A6 | مشارك خبيث داخل محادثة | مفتاح فك تشفير شرعي للمحادثة | تسريب/إعادة نشر، انتحال داخل المحادثة، حفظ نسخ — لا يمكن منعه تقنيًا بالكامل، ويُدار بالسياسات |
| A7 | جهاز مفقود/مسروق | وصول للجهاز نفسه | الوصول للمحتوى المفكوك على الجهاز؛ يجب ألا يكشف أجهزة/محادثات أخرى |
| A8 | برمجية خبيثة على جهاز موظف | قراءة ذاكرة العميل بعد فك التشفير، Keylogger، سرقة ملفات الجلسة | تجاوز E2EE من نقطة النهاية — خارج نطاق الضمان، ويُخفف بصلابة الأجهزة والتحديثات |
| A9 | اختراق قناة تحديث الواجهة | استضافة واجهة معدومة تسرق المحتوى بعد فك التشفير | كسر E2EE من العميل — يُخفف بتحقق نزاهة البناء والتوقيع وSRI |
| A10 | مراقب بيانات وصفية | رؤية أحجام/أوقات/جهات التواصل | استنتاج أنماط التواصل — يُخفف بالتقليل والتجميع، ويُعلن كحد تقني |

## 1.5 أهداف أمنية قابلة للتحقق

1. **سرية المحتوى:** A2 وA4 وA5 لا يستطيعون استخراج نص أي رسالة من قاعدة البيانات أو API مهما بلغت صلاحياتهم.
2. **سلامة المحتوى:** أي تعديل على ciphertext أثناء التخزين أو النقل يُرفض عند فك التشفير (فشل مصادقة واضح للمستخدم).
3. **مصادقة المشاركين:** لا يستطيع A3 تمرير جهاز وهمي كمستلم دون اعتماد من جهاز موثوق ودون ظهور الحدث في سجل الشفافية وإشعار المستخدم.
4. **السرية المستقبلية للمجموعات:** إزالة عضو (A6 سابقًا) أو إبطال جهاز يمنعهما من فك تشفير الرسائل اللاحقة فور Commit — ضمان MLS الأصلي.
5. **استقلالية الاستعادة:** إعادة تعيين كلمة المرور من المسؤول لا تكشف ولا تلمس مفاتيح التشفير إطلاقًا.
6. **تدقيق بلا أسرار:** سجل التدقيق يثبت الأفعال دون تسجيل أي مادة سرية.

## 1.6 الحدود الصريحة (Non-Goals) — تُعلن للإدارة والمستخدمين

- E2EE لا يحمي من جهاز موظف مخترق بالكامل (A8) أو من تصوير الشاشة/النسخ اليدوي — تُدار بالسياسات وصلابة الأجهزة.
- E2EE لا يخفي بيانات الوصفية بالكامل (من كتب لمن ومتى وحجم المرفقات) — يُقلّص ويُقيّد، وإخفاء أنماط التواصل بالكامل يحتاج تقنيات أخرى.
- النسخة المؤسسية من مراسلة رسمية **قابلة للقراءة من المستلم المؤسسي المخوّل** بمفتاحه هو — هذا تصميم معلن وليس ثغرة.
- الرسائل التي فُكّ تشفيرها شرعًا عند عضو خبيث لا يمكن سحبها (A6).
- الضمان القانوني «توقيع إلكتروني نظامي» لقرارات الاعتماد غير مطلوب في هذه المرحلة؛ نستخدم توقيع قرار تشفيري موثق للنزاهة فقط.
